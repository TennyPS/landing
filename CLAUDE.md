# Карта проекта (для тех, кто видит его впервые)

## Что это и в чём идея

Лендинг Татьяны Коновой «Отдел продаж под ключ» для собственников малого и среднего бизнеса (чаще производство или небольшая торговля), у которых продажи держатся на них самих и одном продавце, а системы нет.

Татьяна проводит аудит продаж и строит отдел продаж: воронку в CRM, скрипты, регламенты, KPI, мотивацию. ИИ лишь ускоряет подготовку черновиков документов; продаётся результат, а не нейросеть.

Задача страницы: за десять секунд объяснить, что это, для кого и зачем, и привести человека к сообщению Татьяне в Telegram (@tennydm). Входов два:

- **Генератор «Ваш отдел продаж»** (MVP, главный вход). Человек выбирает тип бизнеса (производство, IT, услуги), вводит пять чисел (средний чек, заявки в месяц, доля оплат, число продавцов, длина сделки) и сразу видит воронку, KPI, аналитику с ползунком «а что если» и короткий скрипт первого контакта. Всё считается в браузере, ничего не сохраняется и не отправляется. Под результатом кнопка «Разобрать результат со мной» с введёнными данными в Telegram-фразе.
- **Проверка отдела продаж (PDF)**, запасной вход. Кнопка в Telegram, PDF Татьяна присылает вручную.

Жёсткие правила: никаких выдуманных цифр, отзывов и «средних по рынку»; название клиента-примера не называем без его согласия; тон тёплый, от первого лица.

Подробности: `docs/superpowers/specs/2026-10-20-landing-design.md` (сам лендинг) и `docs/superpowers/specs/2026-10-22-mvp-generator-design.md` (генератор; при расхождениях главнее он).

## Что где лежит

- `index.html` — вся страница (HTML, CSS и скрипт генератора внутри, без внешних библиотек и картинок).
- `templates.js` — шаблоны типов бизнеса (названия, этапы воронки, значения по умолчанию). Подключается к странице отдельным файлом, чтобы Таня правила данные, не трогая вёрстку. Всё, что не вычитано, помечено словом «ЗАГЛУШКА»; пока оно есть, ветку `mvp-generator` в `master` не вливаем.
- `docs/superpowers/specs/` — документы дизайна: что строим и почему.
- `docs/agents/` — настройки для скиллов: где живут задачи, какие метки, как читать доменные документы.
- `.superpowers/` и `check/` — служебные папки, в git не попадают.
- PDF-проверка и её исходник лежат вне репозитория, в `StartUp/checklist/`, чтобы не быть открытыми по прямой ссылке.

## Технические ограничения (не нарушать)

- Страница живёт на GitHub Pages: только HTML, CSS и JavaScript в браузере.
- Нет сервера, базы данных, API-ключей, платных сервисов, библиотек и шрифтов из интернета.
- Работает с телефона: одна колонка, крупные поля, без горизонтальной прокрутки.

## Как сайт публикуется

GitHub Pages, ветка `master`, корень репозитория. Достаточно сделать commit и `git push` в `master`: через минуту-две страница обновится на https://tennyps.github.io/landing/. Репозиторий публичный: всё, что в нём лежит, видно всем.

## Как мы работаем

Одна задача на GitHub = одна новая сессия. Задачи ведём в GitHub Issues этого репозитория (https://github.com/TennyPS/landing/issues). Берём одну задачу, открываем новую сессию Claude Code, делаем, коммитим, пушим, закрываем задачу. Так контекст не раздувается, а каждая задача остаётся маленькой и проверяемой.
